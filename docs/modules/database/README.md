# Database Module

The database foundation is async-first and SQLAlchemy 2.x based.

## Components

~~~text
Pydantic Settings

      v
async_sessionmaker

request/application-scoped AsyncSession

Repository / application service
~~~

PostgreSQL is the production target. SQLite + aiosqlite supports lightweight local development and tests.

## Migrations

Alembic owns schema history. The repository includes the foundation and optional identity schema revisions.

~~~bash
make migrate-up       # upgrade to latest revision
make migrate-down     # downgrade exactly one revision
make migrate-current  # show current database revision
make migrate-history  # show migration history
make migrate          # alias for migrate-up
~~~

For a new revision:

~~~bash
uv run alembic revision --autogenerate -m "describe schema change"
~~~

Autogenerated migrations must be reviewed before committing. Never edit an already-applied migration in place.

## Production rules

- Do not use Base.metadata.create_all() as a production migration mechanism.
- Keep migrations small and reversible where practical.
- Run migrations once as an explicit release step before the application rollout.
- Do not run migrations independently from every API process.
- Do not put credentials in migration files.
- Verify migration behavior against PostgreSQL before release.

See MVP acceptance tracker (../../MILESTONES.md) for the current verification gates.
