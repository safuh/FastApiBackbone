# Database Module

The database foundation is async-first and SQLAlchemy 2.x based.

## Components

```text
Settings
  ↓
AsyncEngine
  ↓
async_sessionmaker
  ↓
request-scoped AsyncSession
  ↓
Repository / application service
```

PostgreSQL is the production target. SQLite + `aiosqlite` exists for lightweight development and tests.

## Migrations

Alembic owns schema history. Product applications own their models and migration revisions.

Direct Alembic commands remain available, while the Makefile provides stable migration helpers:

```bash
make migrate-up       # upgrade to the latest revision
make migrate-down     # downgrade exactly one revision
make migrate-current  # show the database's current revision
make migrate-history  # show migration history
make migrate          # alias for migrate-up
```

For a new revision, use Alembic directly:

```bash
alembic revision --autogenerate -m "describe change"
```

Autogenerated migrations must always be reviewed before committing. Schema changes are production code.

## Production rules

- Do not call `create_all()` as a production migration mechanism.
- Keep migrations small and reversible where practical.
- Avoid long blocking DDL in live deployment paths.
- Run migrations as an explicit deployment step.
- Do not put credentials in migration files.
- Integration tests must execute against PostgreSQL before v1.0.

See [`../../MILESTONES.md`](../../MILESTONES.md) for the remaining database acceptance gates.
